# Выгрузка результатов пилота

В «Планировщике» нажмите **«Экспорт JSON»**. Выгрузка копируется в буфер обмена; сохраните её в файл для исследователя. Код участника связывается с файлом во внешней таблице и в приложении не запрашивается.

Полное время планирования измеряется внешним таймером и дневником на обеих неделях. Разность между генерацией и принятием плана не является этим показателем. Выгрузка не рассчитывает время планирования, итоговые проценты или критерии значимого шага. Исходные критерии и сроки фиксируются в протоколе пилота.

## Формат JSON, версия 2

| Поле | Содержание |
| --- | --- |
| `schemaVersion` | Версия формата: `2`. Ранее экспорт содержал только массив событий. |
| `exportedAt` | Время выгрузки в UTC, ISO 8601. |
| `taskLists` | Списки задач: `id`, `name`, `color`. |
| `tasks` | Текущее состояние задач, включая `id`, `listId`, `isDone`, `completedAt`, даты, оценку длительности, тексты и ID шагов. У действия `parentTaskId` указывает на исходное дело, `sourceStepId` — на его шаг. |
| `plans` | Последние принятые планы по дням; порядок состава задан массивом `selectedTaskIds`. |
| `events` | Журнал событий в порядке записи, от ранних к поздним. `sequence` задаёт порядок, в том числе при совпадении времени. |

`completedAt` содержит фактическое время последнего перехода в выполненное состояние в UTC с точностью до миллисекунд (точность хранения DateTime в Hive). Повторная установка уже выполненного статуса не меняет его. Отмена выполнения очищает текущее `completedAt`, а прежняя дата остаётся в событии отмены. У старых выполненных задач с неизвестной датой сохраняется `null`.

## События и восстановление

У событий есть собственный `id`, `type`, время `timestamp` и идентификаторы связанных сущностей.

| `type` | Значение |
| --- | --- |
| `plan_generated` | Действительная генерация предложения плана. |
| `plan_changed` | Изменение состава, порядка или бюджета черновика. Повторное применение тех же значений не создаёт изменения. |
| `plan_saved` | Принятие плана; прежнее имя события сохранено для совместимости. `planSnapshot` содержит отдельный снимок принятой версии. |
| `task_completed` | Переход задачи или действия в выполненное состояние. |
| `task_completion_undone` | Отмена выполнения; `previousCompletedAt` сохраняет отменённую дату, если она известна. |

Для анализа принятой версии используйте `planSnapshot` соответствующего `plan_saved`, а не текущие поля задачи. `acceptanceId` различает принятые версии; `savedAt` задаёт время принятия. В `taskSnapshots` по ID задачи сохраняются состав, названия, исходные даты планирования и дедлайны, длительности и связи. Последующие правки и удаление задач не переписывают эти сведения. Ранее сохранённые данные, у которых таких снимков ещё не было, не получают выдуманных исторических значений.

При первом изменении плана старого формата `previousPlanSnapshot` сохраняет его прежнюю запись целиком. Её отсутствующие даты принятия и идентификаторы не заполняются задним числом. У старых событий без `sequence` порядок берётся из порядка записей в хранилище; их исходные временные метки сохраняются.

Для восстановления последовательности выполнений просматривайте события по `sequence`, используя `taskId`, `parentTaskId` и `sourceStepId`. `task_completed` добавляет выполнение, `task_completion_undone` отменяет его; последующее выполнение — новый переход. Текущие `isDone` и `completedAt` в `tasks` позволяют сопоставить результат с последним состоянием. Неизвестные старые даты остаются неизвестными.
